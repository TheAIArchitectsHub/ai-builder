# AI Builder

Practical AI-building resources from [The AI Architects Hub](https://theaiarchitectshub.com/).

[Website](https://theaiarchitectshub.com/) · [YouTube](https://www.youtube.com/@theaiarchitectshub) · [GitHub](https://github.com/TheAIArchitectsHub)

AI Builder is a public library of instructions, templates, playbooks, checklists, and working examples for people who want to build with AI without the overwhelm. Resources shared through The AI Architects Hub's social channels will have a permanent, easy-to-find home here.

> If a resource helps you, please [star this repository](https://github.com/TheAIArchitectsHub/ai-builder) so you can find it again and help other builders discover it.

## Explore the library

| Section | What you will find |
| --- | --- |
| [Agent instructions](resources/agent-instructions/) | Ready-to-use guidance for coding agents, including `AGENTS.md` and `CLAUDE.md` packs |
| [Templates](resources/templates/) | Reusable briefs, prompts, specifications, and project starters |
| [Playbooks](resources/playbooks/) | Step-by-step workflows for building and shipping with AI |
| [Checklists](resources/checklists/) | Practical quality, security, evaluation, and launch checks |
| [Examples](resources/examples/) | Small, working examples that demonstrate the ideas in practice |
| [Project notes](docs/) | Product and technical decisions for the repository itself |

New resources will be added over time. Each resource will include a short explanation, who it is for, how to use it, and any files you can copy into your own project.

## Start here

1. Browse the [resource index](resources/).
2. Open the category that matches what you are building.
3. Read the resource's `README.md` before copying its files.
4. Adapt the material to your project, team, security requirements, and tools.

Looking specifically for AI coding-agent guidance? Start with [Agent instructions](resources/agent-instructions/).

## How the repository is organised

```text
resources/
  agent-instructions/   AGENTS.md and CLAUDE.md resource packs
  templates/            Reusable project and content templates
  playbooks/            End-to-end implementation guides
  checklists/           Focused review and launch checklists
  examples/             Working demonstrations
docs/                    Repository product and technical notes
src/                     Source code for repository projects
tests/                   Tests and evaluations
```

Every published resource should live in a clearly named folder and include its own `README.md`. This keeps links from social posts stable as the library grows.

## Use responsibly

Treat these resources as starting points, not universal guarantees. Review generated code and content, protect personal and confidential data, test important behaviour, and never commit API keys or other secrets.
